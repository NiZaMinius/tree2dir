**Вставь ASCII-дерево каталогов — получи реальные папки и файлы за секунду.**

Скопируй листинг в стиле `tree` из README, ответа ИИ или собственных
набросков — `tree2dir` превратит его в настоящую структуру на диске.

```
my-app/
├── src/
│   ├── main.rs
│   └── config.rs
├── tests/
│   └── integration_test.rs
├── .gitignore
└── README.md
```
↓
```bash
$ tree2dir --file structure.txt
✔  Successfully generated structure!
  ├── 📁 my-app
    ├── 📁 src
      ├── 📄 main.rs
      ├── 📄 config.rs
    ├── 📁 tests
      ├── 📄 integration_test.rs
    ├── 📄 .gitignore
    ├── 📄 README.md
Done in 2.5ms. Created 3 directories and 4 files.
```

English version: [README.md](README.md)

## Возможности

- **Три режима ввода** — интерактивный TUI, Unix-пайп, или `--file`.
- **Любой стиль отступов** — символы псевдографики (`│├└─`), обычные
  пробелы, табы, или сырой вывод команды `tree`. Глубина считается в
  юникод-символах, а не в байтах, поэтому смешанные стили отступа на одной
  визуальной глубине обрабатываются корректно.
- **Умное определение папок** — достаточно либо завершающего `/`, либо
  того, что у элемента в дереве есть вложенные дочерние строки; размечать
  каждую папку вручную не нужно.
- **Безопасно по умолчанию** — не даёт записать что-либо за пределы целевой
  директории (защита от path traversal), пропускает уже существующие файлы,
  если не указан `--force`, поддерживает `--dry-run` для предпросмотра без
  записи на диск.
- **Быстро** — типичные деревья собираются за единицы миллисекунд.
- **Встроенные комментарии** — `main.rs # точка входа` работает как ожидается:
  комментарий никогда не попадает в имя файла. Флаг `--comments` сохраняет его
  в файле (в синтаксисе комментариев этого файла) или в `COMMENT.md` для папок
  (см. [Комментарии](#комментарии)).

## Установка

```bash
cargo install tree2dir
```

Либо скачай готовый бинарник со страницы [Releases](../../releases) —
доступны сборки под Linux, macOS и Windows.

## Использование

### Интерактивный TUI (режим по умолчанию)

Запусти без аргументов в настоящем терминале:

```bash
tree2dir
```

Вставь или напечатай дерево, затем нажми **Enter**, чтобы собрать структуру
в текущей директории.

### Режим пайпа

```bash
cat structure.txt | tree2dir
```

### Файловый режим

```bash
tree2dir --file structure.txt --output ./my-project
```

### Флаги

| Флаг | Описание |
|---|---|
| `-f, --file <PATH>` | Взять дерево из файла вместо stdin/TUI |
| `-o, --output <DIR>` | Целевая директория (по умолчанию — текущая) |
| `--dry-run` | Показать, что сделал бы настоящий запуск, не трогая диск: существующие папки не считаются, существующие файлы помечаются как пропускаемые (или перезаписываемые с `--force`) |
| `--force` | Перезаписывать уже существующие файлы |
| `-y, --yes` | Пропустить подтверждение |
| `--no-tui` | Никогда не запускать TUI, даже в интерактивном терминале |
| `--comments <MODE>` | Сохранять встроенные `# комментарии`: `none` (по умолчанию), `files`, `dirs` или `all` — см. [Комментарии](#комментарии) |
| `--with-file-comments` | Сокращение для `--comments files` |
| `--with-dir-comments` | Сокращение для `--comments dirs` |
| `--with-comments` | Сокращение для `--comments all` |

`--comments` нельзя сочетать с тремя сокращениями.

## Комментарии

Допиши `# заметку` после имени, и tree2dir воспримет её как комментарий, а не
часть имени. По умолчанию комментарии только показываются в итоговом выводе и
не сохраняются; `--comments` выбирает, что записывать на диск:

| Режим | Что записывается |
|---|---|
| `none` (по умолчанию) | ничего |
| `files` | комментарий каждого файла — внутрь файла, в синтаксисе комментариев его расширения |
| `dirs` | комментарий каждой папки — в `COMMENT.md` внутри этой папки |
| `all` | и то и другое |

```
my-lib/ # небольшая библиотека
├── src/ # исходники
│   ├── lib.rs # публичный API
│   └── util.py # помощники
├── data.json # фикстуры
├── "release notes.md" # показывается на странице релизов
└── README.md # документация
```

`tree2dir --file tree.txt --comments all` создаст:

| Путь | Содержимое |
|---|---|
| `my-lib/COMMENT.md` | `небольшая библиотека` |
| `my-lib/src/COMMENT.md` | `исходники` |
| `my-lib/src/lib.rs` | `// публичный API` |
| `my-lib/src/util.py` | `# помощники` |
| `my-lib/README.md` | `<!-- документация -->` |
| `my-lib/release notes.md` | `<!-- показывается на странице релизов -->` |
| `my-lib/data.json` | *(пусто)* |

Что полезно знать:

- **Файлы неизвестных типов остаются пустыми.** Комментарий пишется только для
  расширений с известным синтаксисом комментариев (`rs`, `js`, `ts`, `py`,
  `sh`, `yml`, `toml`, `sql`, `html`, `md` и ещё несколько десятков). Всё
  остальное — `json`, `css`, `txt`, `env`, картинки, архивы, файлы без
  расширения — создаётся пустым, чтобы ничего не испортить.
- **Одна строка на комментарий**, с переводом строки в конце. Переводы строк,
  управляющие символы и всё, что закрыло бы комментарий досрочно (например,
  `-->`), нейтрализуются, поэтому комментарий не может внедрить код в
  создаваемый файл.
- **Без `--force` ничего не перезаписывается**: ни существующий файл, ни
  существующий `COMMENT.md` (предупреждение объяснит, что пропущено). Если
  `COMMENT.md` указан в самом дереве, он главнее сгенерированного.
- **`--dry-run`** показывает каждый комментарий, который был бы записан.
- **Где `#` начинает комментарий.** После пробельного символа (пробел или таб):
  `notes#1.txt` и `C#/` сохраняют свой `#`. Строка, которая начинается с `#`
  — даже за символами дерева, как `│   # helpers`, — это строка-комментарий и
  ничего не создаёт. Чтобы назвать элемент, начинающийся с `#`, возьми имя в
  кавычки: `"#recycle"/`.
- **Имена с пробелами или `#`** можно брать в кавычки `"…"` или `'…'`:
  `"my dir"/ # заметки`.

## Хоткеи в TUI

| Клавиша | Действие |
|---|---|
| `Enter` | Подтвердить и собрать структуру |
| `Shift+Enter` / `Alt+Enter` | Перенос строки при вводе |
| `Ctrl+V` | Вставить из системного буфера обмена |
| `Ctrl+E` | Загрузить встроенный пример дерева |
| `Ctrl+R` | Очистить поле ввода |
| `Esc` / `Ctrl+C` | Выйти, ничего не записывая на диск |
| Стрелки, `Home`, `End` | Перемещение курсора |
| `Backspace`, `Delete` | Редактирование текста |

## Как устроен парсер

Отступ измеряется подсчётом **юникод-символов** (`.chars().count()`) в
ведущем префиксе строки (пробелы/псевдографика), а не в сырых байтах. Это
важно, потому что `│` занимает 3 байта в UTF-8, тогда как пробел — 1 байт;
сравнение по длине в байтах давало бы неверную глубину. Подсчёт именно
символов означает, что префикс на основе `│` и эквивалентный по ширине
префикс из пробелов всегда считаются одной и той же глубиной, независимо
от локали или шрифта терминала.

Строка классифицируется как **папка**, если выполняется одно из условий:
1. имя заканчивается на `/`, либо
2. следующая непустая строка во входных данных имеет отступ на один
   уровень больше (то есть у элемента есть дочерние элементы).

Иначе элемент считается **файлом**. Это значит, что завершающий слэш не
обязателен — сырой вывод команды `tree` (который обычно его не проставляет)
разбирается корректно "из коробки".

## Безопасность

Перед любой записью на диск каждый итоговый путь проверяется относительно
корневой директории вывода: элементы не могут использовать `..`,
абсолютный путь или префикс диска Windows, чтобы выйти за пределы целевой
папки. Проверка выполняется и на сыром сегменте пути, и на итоговом
собранном пути — так что защита сохраняется, даже если что-то проскочило
первую проверку.
